It is the overlay's separate Flutter entry point and is now dead code. A delta

=====================================================================
YOUR TEST DECIDED THIS
=====================================================================
"Appear on top" was already off on your phone, and the azan still played and the
notification still arrived. So the overlay was contributing nothing — the service
plays the audio itself and the notification carries a full-screen intent.

It was costing:
  - SYSTEM_ALERT_WINDOW, the permission Google scrutinises hardest
  - a native plugin, flutter_overlay_window
  - a second Flutter entry point, overlay_main.dart
  - APK size

All to duplicate something that already worked. Removed.

=====================================================================
ONE SIDE EFFECT WORTH KNOWING
=====================================================================
The removed code was the ONLY thing that showed a full-screen azan screen over
another app while the phone was UNLOCKED and in use. With it gone, if a prayer
arrives while you are using WhatsApp you get a heads-up notification rather than a
takeover screen.

That is standard behaviour for alarm apps and, I would argue, better manners. But
it is a real change, so judge it yourself during testing.
